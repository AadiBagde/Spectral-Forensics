## 2. Executive summary

Spectral Forensics is an experimental forensic system that investigates
whether an image is REAL or AI-generated by analysing frequency-domain
patterns. It uses 2D Fast Fourier Transform (2D FFT), spectral
representations, engineered features, and machine-learning
classification. A Streamlit application will provide single-image
analysis, batch processing, spectral visualisation, and report
generation.

Main capabilities: - Validate and preprocess the dataset. - Compute 2D
FFT, shifted magnitude/power spectra, and log-spectrum
representations. - Extract radial profiles and additional interpretable
spectral features. - Visualise and statistically compare REAL and FAKE
spectra. - Train and evaluate baseline ML classifiers. - Test
sensitivity to JPEG compression, blur, and resizing. - Provide
single-image and batch inference in a Streamlit dashboard. - Generate
PDF reports with SHA-256 hashes, model information, visual evidence,
results, and limitations.

This is an educational research prototype, not a definitive authenticity
oracle. A model prediction is not proof of provenance.

## 3. Problem statement and motivation

Generative systems can produce realistic images that are difficult to
classify by visual inspection alone. Some image-generation pipelines may
leave statistical or periodic artefacts associated with synthesis and
upsampling. Such patterns can sometimes be investigated in the frequency
domain, where spatial structures may appear as spectral energy
distributions or peaks.

The project tests whether frequency-domain features are useful for
separating REAL and AI-generated images in the selected dataset, whether
ML models can learn those signals, and how performance changes after
common image transformations.

**Scientific caution:** do not assume that every AI-generated image has
the same artefacts, that all fake images have more high-frequency
energy, or that authentic photographs have a uniform spectrum. Results
depend on the dataset, generators, image content, and post-processing.
Measure and report what the actual data shows.

## 6. Technical pipeline

### 6.1 Preprocessing

For each image: 1. Load safely and record original dimensions, format,
and colour mode. 2. Convert to a consistent representation. Grayscale is
the baseline; a luminance-channel experiment may be added separately. 3.
Resize to a fixed resolution, initially 256 × 256, using a documented
resampling method. 4. Convert pixels to floating point and normalize to
\[0, 1\]. 5. Optionally evaluate windowing to reduce boundary effects,
but apply it consistently and document the experiment. 6. Log files that
cannot be read rather than silently ignoring them.

### 6.2 2D FFT

For a preprocessed image array `I`: 1. Compute `F = np.fft.fft2(I)`. 2.
Center zero frequency using `np.fft.fftshift(F)`. 3. Compute magnitude
`M = abs(F)`. 4. Compute power `P = M ** 2`. 5. Use a documented log
transform such as `log1p(P)` for visualisation/features where
appropriate.

Magnitude, power, and log-power are different representations. Name them
correctly and do not treat them as interchangeable.

### 6.3 Radial spectrum

For the shifted spectrum, calculate each pixel's distance from the
frequency-space centre, group pixels into integer-radius bins, and
average the selected spectrum values within each bin. This turns a 2D
spectrum into a fixed-length 1D feature vector.

At 256 × 256 resolution, 128 radial bins are a reasonable baseline.
Clearly document whether the feature is mean magnitude, mean power, or
mean log-power. The initial baseline may use mean log-power to compress
the dynamic range.

### 6.4 Additional features

Investigate meaningful features such as: - Radial spectrum bins. - Low-,
mid-, and high-frequency energy. - High-frequency energy ratio. -
Spectral centroid and spread. - Spectral entropy and variance. -
Dominant non-DC peak frequency and peak magnitude. - Number/prominence
of candidate peaks. - Horizontal and vertical spectral symmetry.

Define features precisely, handle numerical edge cases, and exclude the
DC component where appropriate. Do not inflate feature count with
redundant or unexplained metrics. Evaluate whether features provide
useful class separation.

### 6.5 Visual and statistical analysis

Generate plots from actual dataset calculations: - Original image and
its FFT log-spectrum. - Radial profile for selected REAL and FAKE
examples. - Mean REAL and FAKE radial profiles, with variability where
useful. - Overlaid REAL-vs-FAKE spectrum comparison. - Feature
distribution plots. - Summary statistics and sample counts. - Optional
correlation and univariate separability analysis.

Do not use fabricated curves or example values as if they were
experimental results.

## 7. Team architecture: eight main scripts

### Student 1 --- Frequency-domain forensics

**1. `student1_preprocessing.py`** - Validate train/test/class
folders. - Count images by split and class. - Record dimensions,
formats, colour modes, unreadable files, and exclusions. - Apply
consistent preprocessing and save metadata/manifests. - Never overwrite
raw inputs.

**2. `student1_fft_analysis.py`** - Implement 2D FFT, FFT shift,
magnitude, power, and log-spectrum functions. - Produce spectral arrays
and representative visualisations. - Keep mathematical operations in
reusable shared functions.

**3. `student1_spectral_features.py`** - Extract radial spectrum and
documented engineered features. - Generate `train_features.csv` and
`test_features.csv`. - Include labels and relative path/split
metadata. - Save feature configuration so inference can reproduce the
same feature order.

**4. `student1_spectral_visualization.py`** - Create
original-image/FFT/radial-profile figures. - Compare REAL and FAKE
aggregate spectra. - Generate feature distributions and summary
statistics. - Save figures and tables under
`reports/spectral_visualizations/`.

Student 1 owns preprocessing, FFT, feature engineering, and descriptive
spectral analysis. Student 1 does not own final ML benchmarking or the
dashboard.

### Student 2 --- ML, attribution experiments, and robustness

**5. `student2_ml_classifier.py`** - Load generated features. - Validate
labels, missing values, and feature consistency. - Establish baseline
models: Logistic Regression, Random Forest, and SVM; XGBoost is
optional. - Use a validation split or cross-validation within training
data. - Fit scaling and model operations inside a scikit-learn Pipeline
when required. - Evaluate once on the held-out test split after model
selection. - Save model, metrics, confusion matrix, configuration, and
metadata.

**6. `student2_generator_analysis.py`** - Perform generator/source
attribution only if verified source labels and enough examples per
source exist. - The current folder structure only establishes REAL/FAKE.
If generator labels are unavailable, report that attribution is
unsupported by the current dataset and document the data needed for
it. - Do not claim to distinguish Stable Diffusion, Midjourney, DALL·E,
GANs, or any specific generator from binary labels alone.

**7. `student2_robustness.py`** - Apply controlled JPEG re-encoding,
blur, resize/downscale-upscale, and optionally noise to held-out test
images. - Use the same preprocessing and inference pipeline as the
original evaluation. - Report metrics and confusion matrices for each
transformation and compare against the unmodified test set. - Do not
retrain on transformed test data for the primary robustness result.

### Student 3 --- Application and reporting

**8. `student3_dashboard.py`** - Build a multi-tab Streamlit
application. - Use shared inference and feature functions; do not
reimplement preprocessing independently. - Provide single-image
inspection, batch/ZIP processing, spectral plots, predictions, and CSV
export. - Provide interactive JPEG/blur/resize demonstrations where
supported. - Generate a PDF forensic report with ReportLab. - Display
limitations and model details clearly.

## 10. Evaluation requirements

-   Start with simple baselines before adding complexity.
-   Candidate models: Logistic Regression, Random Forest, SVM; XGBoost
    optional.
-   Keep the test split untouched during feature selection and tuning.
-   Use training-only validation or cross-validation for model
    selection.
-   Use scikit-learn Pipelines for scaling and estimators when
    appropriate.
-   Report accuracy, precision, recall, F1, confusion matrix, and
    ROC-AUC where valid.
-   Include per-class metrics and support counts.
-   Record random seeds, feature settings, model settings, and
    dependency versions.
-   Save model and feature configuration needed for consistent
    inference.
-   Check duplicates, leakage, and accidental use of filenames/source
    metadata as predictive features.
-   Never report assumed or illustrative metric values as actual
    results.

## 11. Robustness experiments

Use the same held-out images in original and transformed forms: - JPEG
quality levels. - Gaussian blur strengths. - Downscaling and
upscaling. - Optional mild noise.

Record the transformation settings and report accuracy, precision,
recall, F1, and confusion matrix for each condition. Distinguish a live
one-image dashboard demonstration from formal test-set robustness
results.

-   Allow controlled JPEG quality, blur, or resize settings.

## 17. Limitations and responsible interpretation

-   The current reported dataset has 1,122 images, so generalisation to
    unseen generators, camera sources, domains, and processing pipelines
    may be limited.
-   Binary labels do not necessarily support generator attribution.
-   Compression, resizing, screenshots, filters, and social-media
    processing may change spectral evidence.
-   Real photographs can be edited, and AI-generated images can be
    post-processed.
-   A high score is not proof of provenance or intent.
-   Present results as experimental forensic indicators with metrics,
    dataset details, and limitations.
-   Do not use the system as the sole basis for legal, disciplinary,
    employment, or other high-impact decisions.

## 18. Research context

The project is motivated by work on frequency-domain deepfake detection,
including: - Frank et al., *Leveraging Frequency Analysis for Deep Fake
Image Recognition* (ICML 2020). - Alam, Muneer, and Woo, *UGAD:
Universal Generative AI Detector utilizing Frequency Fingerprints*. -
Cai et al., *Robust AI-Synthesized Image Detection via Multi-feature
Frequency-aware Learning* (2025 preprint).

These papers motivate the investigation; they do not guarantee that this
implementation will reproduce their reported performance. Evaluate the
project's actual dataset and report measured outcomes.
